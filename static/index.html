📖 System Documentation & Architectural Specification

Smart Campus Classroom Management System (SCCS) • Deen Dayal Upadhyaya Gorakhpur University (DDUGU)

v1.0.0 Production Architecture

The SCCS was developed to eliminate scheduling collisions, double-booking incidents, and examination miscommunication across the Institute of Engineering & Technology (IET) (Ground, 1st, 2nd floors) and Deeksha Bhawan (~100m walking distance, 14 lecture halls) serving 6 engineering branches (CSE, AI ML, AI DS, ECE, ME, IT) across 4 academic years.

🎯 The Core Problem & Root-Cause Elimination

The Incident Solved: During the NSS Minor Examination, multiple faculties claimed Room G-01 and LH-04 simultaneously via uncoordinated paper notices and informal WhatsApp messages. Students arrived to find two concurrent exams scheduled in the same hall, forcing emergency relocations across the 100-meter corridor between IET and Deeksha Bhawan, causing severe delay and confusion.
1. Mathematical Overlap Engine

All reservation attempts run through an automated interval-intersection verification algorithm. Overlaps are blocked with HTTP 409 Conflict at the database level.

2. Distance-Aware Alternative Recommender

When a room is occupied, the heuristic scoring algorithm penalizes Deeksha Bhawan by 15 points due to the 100m walking distance, prioritizing vacant rooms on the same floor first.

3. Synchronized Single Source of Truth

Live 2D floor blueprints, branch timetables, CSV exports, official notices, and student grievance channels read from a unified, synchronized database with full audit logging.

⚙️ Algorithmic Engine & Mathematical Formulations

A. Temporal Interval Overlap Detection

Given an existing booking interval [S₁, E₁) and a requested booking interval [S₂, E₂) on date D:

Conflict = (S1 < E2) AND (S2 < E1)
Equivalent: max(S1, S2) < min(E1, E2)

If this evaluates to true for any non-cancelled reservation in the target room, the booking is rejected immediately and the heuristic recommendation pipeline is triggered.

B. Heuristic Alternative Room Fit Scoring

Candidate rooms are ranked dynamically using a multi-factor fitness function normalized to [0, 100]:

Fit Score = max(0, 100 - C_pen - D_pen + B_floor + B_smart)

• C_pen = (Room_Capacity - Students_Needed) × 1.5
• D_pen = 15 pts if Deeksha Bhawan (~100m away)
• B_floor = +10 pts if same floor as requested
• B_smart = +15 pts if projector & smartboard matched

Only rooms with adequate capacity (Capacity ≥ Students Needed) are evaluated, and results are returned sorted in descending score order.

🔄 End-to-End Operational Workflows

FLOW 1 Faculty Room Reservation & Conflict Resolution
  1. Search & Select: Faculty navigates to Room Discovery & Booking, inputs Date, Start/End Time, Branch, and Expected Capacity.
  2. Collision Evaluation: The backend queries existing bookings for that room and time window.
  3. Conflict Handling (if occupied): The system blocks the reservation, highlights the conflicting class/exam, and automatically calculates alternative available rooms scored by capacity and proximity.
  4. One-Click Booking: Faculty selects the recommended alternative, confirms with one click, and receives a confirmed booking record.
  5. Audit & Notification: The booking is recorded in the permanent audit trail and instantly reflected on the live 2D Blueprints and Academic Timetable.
FLOW 2 Student Conflict Reporting & Grievance Resolution
  1. Discovery: A student arrives at a classroom and notices a clash, locked door, projector defect, or unscheduled exam.
  2. Submission: The student opens Conflict & Issue Reports, enters the room number, issue type (Double-booking, Facility, Exam clash), and a description.
  3. Triage: The issue immediately appears on the Faculty and Admin dashboards with an "Open" status pill.
  4. Staff Action: Faculty or Admin reviews the complaint, relocates the session if necessary, and marks the report "Resolved" with explanatory staff resolution notes.
  5. Transparency: All students can verify the resolution status and notes directly from their student dashboard.
FLOW 3 NSS Minor Exam Notice & Timetable Synchronization
  1. Notice Broadcast: Faculty publishes an urgent Minor Examination announcement specifying Date, Time, Room, and Target Branch.
  2. High Priority Banner: The notice is flagged as "High" priority, pinning it to the top of the Announcements tab with a black outline badge.
  3. Timetable Integration: Students filter the Academic Timetable by their branch/year, seeing the newly reserved exam slot immediately.
  4. Offline Export: Students or CRs click "Download CSV" to get a portable spreadsheet of all branch examinations for offline reference.

🚀 DevOps, Deployment & Local Runbook

1. Run Locally (Python 3.10+)
git clone https://github.com/ayushsrivastav9598-glitch/sccs.git
cd sccs
pip install -r requirements.txt
python -m uvicorn main:app --reload --port 8000

Open http://127.0.0.1:8000 in your browser. Database auto-initializes and seeds with sample data on startup.

2. Docker & Containerization
docker build -t ddugu-sccs .
docker run -p 8000:8000 ddugu-sccs
# Or with Compose:
docker-compose up --build

Production-ready multi-stage Dockerfile with non-root security user and automated health checks.

3. Cloud Deployment (Render.com)

Since SCCS requires a persistent Python/FastAPI backend with SQLite database write access, Render.com or Railway is ideal (not GitHub Pages, which is static-only).

Build Command: pip install -r requirements.txt
Start Command: uvicorn main:app --host 0.0.0.0 --port $PORT

Configured automatically via render.yaml in the repository root.

📋 Roles & Permissions Guide

SCCS uses Role-Based Access Control (RBAC) to ensure security, prevent scheduling overlaps, and avoid examination miscommunication.

🎓 Student Role
Allowed: Live 2D vacancy blueprints, branch timetable, download CSV, read exam notices, submit conflict reports.
Prohibited: Cannot book, reschedule, or cancel rooms.
👨‍🏫 Faculty Role
Allowed: Search rooms, book extra lectures / minor exams / labs, conflict blocker & alternatives, reschedule/cancel OWN bookings, post notices, resolve student reports.
Prohibited: Cannot cancel other faculties' reservations.
🛡️ System Administrator
Allowed: Campus-wide overrides, override ANY reservation, full audit trail access, manage room capacities, moderate notices, resolve grievances.
